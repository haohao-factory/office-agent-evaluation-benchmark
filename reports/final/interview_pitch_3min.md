# 3分钟项目介绍初稿

我做的是一个 Office Agent Evaluation Benchmark。起点是我发现办公 Agent 的质量不能只看回答是否像人：它可能把邮件内容说对，却发给错误对象；也可能日历超时后重复创建会议。因此我把任务拆成邮件、日历、文档、表格、文件、联系人、研究和跨工具流程，并把安全、澄清、确认和状态变更作为一等评测对象。

实现上，我用 LangGraph 做单 Agent 工具循环，用可重置的 Mock Office Environment 模拟邮件、日历、权限和文件状态。每题都有隔离运行快照，记录工具轨迹、最终回复和最终状态。评测不是只比答案，而是结合规则、状态和任务验收；高风险、澄清、确认与异常会进入复核。

项目先有 Smoke 20 保障工程，再用 Development 50 做 Bad Case 分流和回归，最后使用独立 Formal 100 做冻结盲测。过程中最典型的发现是：Formal v1 的 100 个失败并不是 Agent 失败，而是评分器把成功工具结果中的空 error 当成对象读取，导致自身异常。我保留了原始记录，修复评分器并补测试后，重新构建独立 Formal v2，而不是覆盖旧结果。

最终 Formal v2 在冻结 Agent、模型、环境和评分器后一次运行 100/100 通过，运行、安全和关键失败均为 0。这个结果只说明当前 Mock 环境、当前模型和当前独立题集下的表现，不代表真实企业生产 100%。我认为这个项目最重要的价值是把 Agent 的能力问题、评测系统问题和任务定义问题分开，并让结果可复现、可审计。
